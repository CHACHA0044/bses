Software Requirement Specification (SRS)
Project Title
BSES Consumer Registration & Dashboard Management System
________________________________________
1. Objective
Develop a secure, responsive web application that enables prospective and existing electricity consumers to register, authenticate, and manage their electricity service requests through a centralized dashboard.
The application shall provide:
•	Secure user registration and authentication 
•	Online application for a new electricity connection 
•	User dashboard for tracking requests and profile information 
•	Administrator dashboard for managing users and connection requests 
•	Database management of registered consumers and service requests 
The proposed solution modernizes the existing registration workflow using contemporary web technologies while maintaining compatibility with consumer information and future utility services.

4. Functional Requirements
4.1 User Registration
The system shall allow users to register by providing:
•	First Name 
•	Middle Name 
•	Last Name 
•	Gender 
•	Email Address 
•	Mobile Number 
•	Aadhaar Number (Optional) 
•	Username 
•	Password 
•	Confirm Password 
•	CA Number (Existing Consumers) 
•	Meter Number (Existing Consumers) 
•	CAPTCHA Verification 
Validation Rules
•	Mandatory field validation 
•	Email format validation 
•	Mobile number validation 
•	Password strength validation 
•	Username uniqueness 
•	CA Number uniqueness (where applicable) 
•	Meter Number verification (where applicable) 
•	CAPTCHA verification 
________________________________________
4.2 User Login
Users shall authenticate using:
•	Username or Email 
•	Password 
The backend shall:
•	Validate credentials 
•	Compare hashed passwords 
•	Generate JWT 
•	Store JWT in HTTP-only cookies 
•	Redirect authenticated users to the dashboard

4.4 New Electricity Connection
The system shall allow users to submit an online application for a new electricity connection.
Application details include:
•	Applicant Information 
•	Property Address 
•	Identity Details 
•	Required Load 
•	Connection Type 
•	Supporting Documents 
•	Declaration 
Users shall be able to:
•	Submit a new application 
•	Save draft applications 
•	Track application status 
•	View application history 
Possible request statuses:
•	Draft 
•	Submitted 
•	Under Verification 
•	Documents Pending 
•	Approved 
•	Rejected 
•	Connection Completed 
This workflow aligns with BRPL's online new connection service.

4.6 Document Management Service (New)
The system shall provide a secure Document Management Service (DMS) for storing, retrieving, and managing consumer documents.
Supported documents include:
•	Aadhaar Card 
•	PAN Card 
•	Address Proof 
•	Ownership Proof 
•	Passport Size Photograph 
•	Affidavits 
•	Other supporting documents 
The DMS shall provide:
•	Secure document upload 
•	Encrypted document storage 
•	Version management 
•	Download authorized documents 
•	Delete documents (when permitted) 
•	View uploaded documents 
•	Maintain document metadata 
•	Link documents to connection requests 
Only authenticated users and authorized administrators shall be able to access documents.

11. DPDP Act Compliance
The application shall comply with the Digital Personal Data Protection Act, 2023 through the following measures:
•	Obtain explicit user consent before collecting personal data. 
•	Collect only the minimum personal information required for providing electricity services. 
•	Encrypt sensitive personal information (e.g., Aadhaar number, identity documents) using AES-256 encryption. 
•	Hash user passwords using bcrypt. 
•	Store uploaded documents securely in MongoDB GridFS while maintaining document metadata in PostgreSQL. 
•	Enforce Role-Based Access Control (RBAC) to restrict access to personal information. 
•	Maintain audit logs for administrative and security-related actions. 
•	Display a privacy notice and obtain consent during registration. 
•	Allow secure deletion or retention of personal data in accordance with organizational policies and applicable legal requirements. 
•	Protect all API communication using HTTPS and secure authentication mechanisms. 
•	Manage encryption keys securely using environment variables or a dedicated secrets management solution.
